# 对接真相清单细则（K1 对接档）

**触发**：证据档 K1 命中（要调用/对接的模块/API/接口，或写入跨模块代码）。**强制级**：M（触发即必须加载）。

## 清单格式（写码前必须填，证据来源空着＝不得动手写）
| 模块 | API/端点 | 对接方式 | 证据来源(source:line 或 官方文档 URL) |
|---|---|---|---|
| 示例：shisan-xinuo-core | discipline_gate 工具定义 | 读源码 | src/shisan-xinuo-core.ts:893-1241 |
| 示例：某 npm 包 | 函数签名/选项 | 官方文档 | https://... |

## 对接强制前置清单（触发对接写码时逐项核实，缺项=不得动手）

| # | 必查项 | 证据要求 |
|---|---|---|
| 1 | 签名/参数 schema | source:line 或官方文档 URL |
| 2 | 返回类型与空/错误形态 | 同上 |
| 3 | 错误契约（异常/拒绝形态） | 同上 |
| 4 | 版本与废弃状态 | K4：联网核实或标「可能过期」 |
| 5 | 权限/作用域要求 | source:line |
| 6 | 副作用（写/网络/全局态） | source:line |
| 7 | 性能/限流特征 | 文档或实测（K5） |
| 8 | 验收用例（可机器判定） | 登记为 discipline_task 断言 |

> 注：与工作区/权限档的关联由**运行时边界守卫**判定（设计要求 D3），**不进提示词**。

## 填写规则
1. 证据来源只认三种真值：**源码行号**（grep/read 实测）、**官方文档 URL**（web_fetch 实证）、**运行时 inspect**（宿主/平台档）。
2. 凭命名直觉、凭训练记忆填写的行＝无效；记不起来就查，查不到就写「未找到证据」并停止写码。
3. 升级形态（跨模块改动）：约束与影响矩阵——每模块列职责/输入输出/依赖与被依赖/权限边界/失败模式/验收用例/变更影响面。答不上「这个改动会扯动什么」就不准进实现。

## 自检
- 每行证据来源非空且可复核（路径:行号或 URL）；
- 版本敏感事实（K4）已联网核实或标注「可能过期」；
- 平台事实（K3）读的是宿主源码/运行时 inspect，不是其他平台的类比。

## 边界
- L1 改名/文案/格式改动不触发本清单；
- 清单填不出时：停下，升级为提问（问用户或查外部），不硬写。
