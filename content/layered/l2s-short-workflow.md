# L2-S 短工作流细则（重构版 · ≤3 文件、单域、与既有模式同构）

**触发**：判级 L2-S，动手写码前。**强制级**：S（动手写码时加载）。

## 步骤（清单，每步有出口产物）
1. **对接真相**（绝不跳过）：写码前填表 `模块 | API/端点 | 对接方式 | 证据来源(source:line)`——grep 调用点 → 读 schema/类型 → 确认包归属 → 才写；命名直觉被禁止。细节见 [docking-truth-list.md](docking-truth-list.md)。
2. **三短行复述**：改哪 / 影响什么 / 怎么验（状态行中文枚举，见常驻核心 §0）。
3. **一行基线**：「改动 + 验收 + 回滚基线」（单文件可直接做；重大改动先按 [templates/rollback-template.md](templates/rollback-template.md) 建回滚点）。
4. **执行 + 最小验证**：可重跑，捕捉退出码；没跑=未完成。
5. **收口＋留档**：discipline_gate（断言或 cmd+claimedExit；弱证据 pass 不闭环，改用 assert 算子）；承载流水一行（时间精确到分）+状态段刷新。

## 自检
- 对接真相表的证据来源非空；答不上「这个改动会扯动什么」就不准进实现。
- 失败用例先行：实现前列了失败用例（每条验收反例＋预期处置），与正向验证同批跑完。
- 最小验证真实跑过、退出码有记录；验收标准与开工复述一致。

## 边界（省什么）
- 免 L2-F 七步全量、免联网双调研、免 plan 文档、免产品三问。
- 不豁免：状态行与判级、必问协议、红线、收口协议、承载留档（流水一行）。
