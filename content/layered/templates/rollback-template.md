# 回滚点模板（固定格式）

**触发**：重大/不可逆操作前（红线强制）；L2 及以上动手前建议。**强制级**：M（命中红线时）。

```markdown
## 回滚点 · <任务名>（YYYY-MM-DD HH:mm）
- 基线：<git commit hash / 备份文件路径（在承载 backups/ 内）>
- 回滚动作：<恢复到基线的一条可执行命令>
- 复验判据（回滚后如何确认恢复成功）：<assert/exists/path_contains 或真实命令>
```

## 备份规则（与承载协议一致）
1. **位置**：备份只允许写进承载文件夹的备份分类子目录（`.xinuo/backups/`），**不越过工作区**。
2. **说明文件**：每个备份必须附 `backup-info.txt`，四要素：
   - 备份时间（到分）：YYYY-MM-DD HH:mm
   - 备份节点：改前 / 改后 / 里程碑
   - 作用：可回滚到哪个状态
   - 原因：因什么而备份（对应哪次操作/哪个决策）
3. **清理**：临时脚本的临时备份**任务完成后直接删除**；除非标 important 的重要备份，其余不留。

## 固定格式要点
1. 备份不替代确认（L3 停点仍需用户确认）——回滚点是「出事能回」，不是「出事不用问」。
2. 回滚点建立后要在承载状态段写「回滚基线」一行，供压缩重载时找回。
3. 无版本控制的环境：备份=复制文件到 `.xinuo/backups/`，路径必须写进回滚点。
