# 外部语料 · 上游规则合规向量（dsh-permission-rules）

> 层6 度量底座·B6。口径：**语料非我方自撰**——它由上游发布，且被**两份独立 DSH 权限 gate 共用**（一份语料、两个消费者、无漂移）。本档在我方验证库中登记该外部语料的来源、哈希与用法。

## 一、它是什么

`dsh-rule-test-vectors/v1`：每个向量 `{ id, purpose, rules (YAML 文本), cases[] }`；每个 case `{ tool, arguments, context?, expect }`，`expect ∈ allow | ask | deny | null(=passthrough)`。**实现中立**——只声明规则文本与期望裁决，不含任何 gate 内部结构，任何第二实现都能据此自证「同语法、同裁决」。

## 三、与本仓的关系

- 本插件的**拦截层（换芯）依赖该上游 gate**（见 [`docs/reuse-decision-permission-rules.md`](../docs/reuse-decision-permission-rules.md)）；因此该 gate 的语法合规是**我方信任链的上游一环**。
- 该语料同时是**上游自证**（其 `test/test-vectors.spec.ts` 用它证明自身一致）与**跨实现契约**（另一份独立 gate 消费同一份）。
- **不等于**我方引擎的语义证据：我方 L3 判定语义由本仓 `tests/rule-corpus.mjs`（170 例；我方 ↔ 上游 **0 不一致**）覆盖。

## 四、怎么自己核

```bash
npm i dsh-permission-rules@0.7.15
node -e "const c=require('node:crypto'),f=require('node:fs');const p=require.resolve('dsh-permission-rules/package.json').replace('package.json','docs/rule-test-vectors/corpus.json');console.log(c.createHash('sha256').update(f.readFileSync(p)).digest('hex'))"
# 期望输出（小写）：8b52083f373662cebe176b6cb09786d0c96816f9b822d1393a2a5c3676db8ee9
```

运行上游自身的向量测试（其仓 `test/test-vectors.spec.ts`）可复验「该 gate 与语料一致」。

## 五、边界（如实）

- 本档是**外部语料登记**，不是我方新增证据；不装上游则无法复跑它。
- 上游语料是**增量式**的、随版本演进；本档锚定 `0.7.15` 的哈希，上游升级后须重核。
