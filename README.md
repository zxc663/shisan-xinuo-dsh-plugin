# shisan-xinuo-dsh-plugin

**DeepSeek Harness（DSH）运行时治理插件**——把「工程纪律」从提示词里的一句建议，变成宿主上**跑不掉的强制**，并带一套**提示词管理后台**。让工作过程**可审计**、危险动作**可拦截**、任务完成**可证明**。

## 它解决什么问题

给 DSH 干活时，常见四类坑：

- 危险操作不打招呼就执行；
- 口头说「验证通过」，其实没跑、或跑的不是那条命令；
- 该做的分级、清单、留档不做，出了事无法复盘；
- 说「任务完成」但没有一条可复核的证据。

本插件在宿主这一层把这些「靠自觉」的事改成「靠机制」：**不是把纪律写得更多，而是把纪律变成运行时强制。**

## 装了什么

### 1. 提示词层（常驻 + 按需）

- `content/discipline.md` —— 常驻核心纪律：状态行、开工协议、证据分级（K0–K6）、承载留档、红线、收口格式。
- `content/layered/` —— 按需加载的流程细则与固定模板，用完即走，不占上下文。
- 全部提示词允许用户修改；改坏自动回退内置默认。
- **自包含**：不依赖外部 Skill 才能运行，外部 Skill 仅可作为可选参考。

### 2. 挂载的工具包

| 工具 | 作用 |
|---|---|
| `discipline_gate` · 收口工具 | 收口时宿主**真实执行**你声明的验证命令，与声称的退出码比对；谎报退出码＝不通过 |
| `discipline_task` · 任务登记 | 开工登记任务清单与验收断言；回合收尾自动复核，未过＝打回 |
| `discipline_tools` · 工具目录 | 只读列出当前真正下发的工具面（线缆真值），不做裁剪 |

### 3. 运行时自动强制（不靠自觉）

- **判级自动检测**：宿主按「工具名 + 命令」独立推风险等级，与自报等级比对，低报也逃不掉。
- **调用工具检测**：按客观副作用（写／删除／执行）判是否需要收口，只读回合自动豁免。
- **L3 危险命令拦截**：命中危险域先拦下、要你确认，未授权不执行。
- **回合收尾复核**：已登记断言由宿主在收尾自动复核，未过即打回，不认「自己说完成了」。
- **遥测对账**：执行日志 + 统计对账 + 密钥脱敏，全程留痕可审计。

### 4. 更严谨的强权限管理

- L3 危险域可配置（`content/rules.json`），域命中即拦；配置损坏自动回退内置默认，**不静默解除防护**。
- 只读豁免规则区分「查看」与「改动」。
- 工作区边界守卫：越界写动作全程记录在案。

### 5. 提示词管理后台（DSH自定义）

内置一套网页管理后台（挂在 DSH 设置区），6 个页签：

- **会话管理**：只读查看每个会话实际装配的提示词；
- **系统提示词管理**：编辑常驻核心／我的提示词／渐进分节，整段接管或恢复官方原文；
- **快照与恢复**：一键备份、时间线回滚、JSON 导入导出；
- **统计数据**：护栏拦截、快照、会话改动等审计流水；
- **治理开关**：L3 总闸＋各危险域逐域开关＋误拦白名单，写 `governance.json` 热生效；
- **关于**：版本、反馈入口、卸载与还原指引。

## 诚实边界（先读，别误会）

- 收口验证是一条**新的执行通道**，不是安全沙箱——清单覆盖之外不拦。
- 退出码比对只抓「谎报」，与目标无关的命令仍会通过。
- 本插件**不保证模型更聪明，也不构成安全边界**——拦截面是枚举覆盖，验证面是真退出码。

## 安装 / 测试

```bash
npm test                          # 全套单测（Node ≥22.18）
node scripts/tally.mjs --report --freeze
```

开发态挂载示例见 `cordis.yml`；发行态经 `dsh plugin add` 使用 `cordis.patch.yml`（指向预编译产物 `lib/`）。
