# shisan-xinuo-dsh-plugin

**DeepSeek Harness（DSH）运行时治理插件**——完整愿景是把「元工作流纪律」落成 DSH 宿主上的三层体系：**元提示词层**（常驻核心＋用户自定义段，全部允许用户修改）＋**工作流与固定模板层**（渐进加载）＋**运行时强制层**（真值收口/边界拦截/强制补判级/审计）。

> ⚠️ **现状声明（先读）**：本仓目前**只实现了完整体系的一部分**，不要把当前实现当作全部。完整体系分三块：
> 1. **提示词内容层**——常驻核心 v8＋layered 渐进加载层＋固定模板：✅ 已落盘（`content/`，本仓就是它的家）；
> 2. **运行时治理核心**——L3 拦截/gate 真值收口/断言自动复核/steer 打回/遥测对账：✅ 已实现（`src/shisan-xinuo-core.ts`，能力矩阵见下）；
> 3. **配置与证据页面（DSH自定义）＋运行时增强批**——提示词中心（可编辑）、用户自定义提示词段、渐进加载保证（检测→注入）、工作区边界守卫、判级强制、提问倒计时、压缩信号：🟡 **规划中，未实现**（见路线）。

## 本质与表象

**本质**：本插件是**治理运行时**——不是工作流执行器、不是提示词库、不是 UI 产品、不是 shisan-xinuo-workflow 的镜像移植。它只做三件可证明的事：**过程可审计、边界可拦截、完成可证明**；不保证「模型更聪明」，**不是安全边界**。

**表象（描述要诀）**：从「它检查什么、强制什么、记录什么、不保证什么」出发，而不是从「工作流步骤」出发——所以骨架=状态总表 → 能力矩阵 → 代价与风险 → 提示词体系 → 路线。

## 提示词体系（全部允许安装用户修改）

- `content/discipline.md` — **常驻核心 v8**：状态行（中文封闭枚举）／开工协议（确认任务/环境盘点/澄清提问/判级/证据 K0–K6）／思考要求与质疑审查（需求四层/三质疑/方案三想一合/调研对比）／承载协议（一档制四区，流水精确到分，备份限定 backups/）／红线／收口与收尾协议（收尾五件＋固定输出格式：交付/验证/改动/待决策/待授权/未决）／工具触发矩阵／渐进加载路由。**用户可修改**——改坏 fail-closed 回退内置默认；页面提供恢复出厂（规划）。
- `content/layered/` — 渐进加载层（细则 8＋模板 6）：M（触发即必须）/S（按症状）标注；同样允许用户修改。**保证机制**（规划）：路由契约＋宿主检测→注入＋缺载后果绑收口＋指纹核对；诚实边界——检测保证「触发时注入」，不保证「模型遵守」，遵守由收口打回兜底。
- **用户自定义提示词段**（规划）：`user-prompt.md` 独立于常驻核心，装配序=常驻核心→用户段→官方。
- `content/rules.json` 规则包；`content/agents-md-discipline.md` AGENTS.md 兜底副本。

## 代价与风险（如实）

- **收口验证是一条新的执行通道**：gate 会真实执行你声明的验证命令——护栏=危险域清单＋被拒指纹（10 分钟），**不是安全沙箱**；清单覆盖之外不拦。
- **一致性≠有效性**：claimedExit 比对只抓「谎报退出码」；与目标无关的命令会通过。
- **动作落地级判据≠目标级判定**（effect-closeout 与 auto-closeout 分列记账）。
- **收口强制在界面上呈现为「用户发言」**（宿主投递接口约束），前缀 `[十三希诺收口强制]` 自曝来源。
- **完全权限下 L3 拦截退位为仅记录**：红线是唯一防线。
- **遥测日志默认明文落盘**（常见密钥形态自动脱敏——非穷尽）。
- 一句话：**不要把本插件当作安全边界**——拦截面=枚举覆盖，验证面=真退出码。
