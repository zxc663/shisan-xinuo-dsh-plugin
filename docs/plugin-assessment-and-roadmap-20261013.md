> **本文的论证纪律（反向论证规则）**：每条主张必须给出**最强反驳**与**处置结论**（采信／驳回／降级）。

## 1. 分块实质效应

| 组件 | 效应判定 | 证据 | **最强反驳** | 处置 |
|---|---|---|---|---|
| L3 拦截（自研正则） | **净负** | regex 模式连坐上游基线致整条目静默失活（B3b 实测「以为在拦、实际没拦」） | 反驳①：那是与上游共存的集成缺陷，不是拦截本身的问题 | **驳回**（自研拦截与上游重复，维护成本高于增量；决策已外置） |
| 工具预算裁剪 | 小正，**仅在工具面大时为正** | 25→8 工具／每请求省 ~11KB（实测） | 反驳①：宿主若本来只有 8 个工具，收益为零而注入成本照付 | **采信**（改为按"净收益>0"才启用） |
| 收口真值化（`discipline_gate`） | **条件性正** | 外部锚 0 误推导；启发式推导 3/13 误报，代价＝1 假阻塞＋1 超时＋2 steered | 反驳①：`claimedExit` 三态只是记账，判定仍靠"模型给的命令" | **部分采信**（语义增量承认；有效性降级为"依赖判据来源"） |
| 收口强制（turn-stopping） | **正，最硬一块** | 真机与 headless 各 1 例：把"谎报完成"转为"如实未收口"，未伪造 GATE | 反驳①：行业已有同型件（Stop hook 家族），存在性无增量；反驳②：n=2 | **采信**（仅主张"语义细节＋真机复现"，不主张稀缺性） |
| 整体成本 | 显著 | 每任务累计上下文 +50%～5.4×；步数 3→6/8 | 反驳①：成本被"任务越难收益越大"抵消 | **驳回**（高能力档实测无靶可抓，成本照付 ⇒ 无条件开启不成立） |

**净增量结论（交集式表述）**：**在有外部锚 ∧ 任务不可逆的交集内为正；交集外近似为税。**

- **最强反驳**：锚由人写 ⇒ 真正的收益属于"人写锚"这件事，插件只是记账本，换任何人写个 `if (!(Test-Path x)) exit 1` 也能得到同样结果。
- **处置**：**采信一半**。反驳成立的部分＝"手工锚场景下插件可被脚本替代"；反驳不成立的部分＝**强制收口**（turn-stopping 阻止回合结束）与**遥测对账**这两件脚本做不到。⇒ 差异化价值收敛为"**强制**＋**对账**"，而非"验证"本身。

## 2. 它回答了什么、没回答什么

- **答了**：完成信号可由宿主**独立复算**（真退出码／文件系统状态），不必依赖自述。地板论证成立。
- **没答**：**判据从哪来**。v1 靠启发式推导（实测负资产），v2 靠外部锚（需人写），v3 靠模型自由写命令（可用率 17–63% 平台期）。
- **最强反驳**：既然问题只剩"判据从哪来"，而判据来自项目既有检查（测试／CI／只读文件）时最稳，那**这个插件对已有完善测试的项目就是多余的**。
- **处置**：**采信**。⇒ 定位收窄：面向**没有现成判据**的任务（一次性删除／迁移／发布），而非有 CI 的项目。

## 3. 改造方案（四选，含反驳）

| 方案 | 做法 | **最强反驳** | 处置 |
|---|---|---|---|
| **A 收缩为锚定收口器** | 删拦截/推导/预算，只留锚＋gate＋强制＋遥测 | 反驳：放弃工具预算与判级接线，等于砍掉一半已实现功能 | 降级为 **C 的子集** |
| **B 扩为判据供给器** | 算子库＋任务模板；pinned 从项目既有检查派生 | 反驳：算子库覆盖不了非文件型任务 | **保留为主方向之一**（先只覆盖资源真值型，其余退回人工） |
| **C 按不可逆性触发的最小干预层** | 触发＝客观事件（写/删/执行 ∧ 不可逆）＋交付声明，弃用自报等级 | 反驳：不可逆性判定本身可能出错 | **选为主路线**（判定用白名单工具类别＋路径域，不用语义推断） |
| **D 并入上游** | 语义贡献给上游引擎／宿主 | 反驳：依赖外部接受，不受本仓控制 | 暂不作主路 |

**选优：C → B**（C 立即净减负；B 是唯一解"判据从哪来"的方向）。

## 4. 实现细节（DSH 挂点实查；均为本机实测结论）

### 4.1 触发层：客观事件替代自报等级

- **可用挂点**：`tools/pre-execute`（可读工具名＋参数）、`session/event`（可读 `tool/call` 序列）、`agent/turn-stopping`（可读回合桶 `toolCalls`／文本）。
- **实现**：以**工具名＋参数键**判定"发生了写／删／执行"，再以**路径域**（是否落在任务目录、是否触及仓库外）判定不可逆性；`声明交付`＝终文命中完成语（与 `judgeZeroToolClaim` 同族）。
- **最强反驳**：工具参数可被伪装（例如用 `pwsh` 执行任意删除）。**处置**：采信 ⇒ 因此本层只决定"**是否进入收口检查**"，不承担拦截；拦截仍归上游引擎（已外置）。

### 4.2 判据供给层：算子库

- **形态**：与既有 pinned 语法同构（`not_exists:<path>`／`exists:<path>`／`path_contains:<path>::<s>`／`cmd_exit0:<cmd>`），新增仅限**纯检查**算子（禁止写入类）。
- **来源优先级**：① 项目既有检查（测试／CI 名）② 只读锚文件 ③ 人工填写 ④ **受约束出题**（模型只在算子参数空间填参）。
- **最强反驳**：`cmd_exit0` 会重新引入任意命令与副作用。**处置**：采信 ⇒ `cmd_exit0` 在**受约束出题**路径下禁用（本轮实现即如此），仅允许人工显式给出。

### 4.3 出题层：受约束出题（本轮已验证的最低要求）

五条硬约束（缺一即回落平台期）：①**无工具**通道（杜绝"调工具代替出题"）；②**候选制**（≤3 条，宿主取首个通过校验者）；③**副作用护栏**（含改写动词一律不执行）；④**执行前后各取一次真值**（`truthAfterAdv`，判据改动状态必须如实记录而非视为通过）；⑤**出题模型选型**＝非思考型（思考型实测 8%／0%，原因＝长推理挤掉结构化输出）。
- **最强反驳**：这些都是"提示词/工程脚手架"，换个更强的模型就不需要。**处置**：**部分采信**（承认受模型能力影响）但反驳不成立于当下可用模型；⇒ 保留为工程要求，并在报告标注"随模型能力提升可放宽"。

### 4.4 成本与熔断

- **KPI 门禁**：每任务步数上限／累计上下文上限／假警报率上限；触顶即**自动退位为纯观测**（依据：本电池出现 29 步离群会话，单次成本高于十次正常任务）。
- **最强反驳**：硬上限会误杀正常长任务。**处置**：采信 ⇒ 上限按"分布 P95"设定并允许显式放行（记录放行理由）。

### 4.5 与上游边界

- 本插件**不碰执行通道**；`gate` 的直跑通道（审计 F-02 指出的风险）保留"被拒指纹＋清单＋仅检查类算子"，并在 README 明写**不作为安全边界**。
- **最强反驳**：只要插件自己 `exec()`，就仍是新执行通道。**处置**：**采信**，此为**结构性残留**，只能缩小不能消除；写入"代价与风险"节。

## 6. 未定论清单（不得当作结论使用）

1. **跨厂商去相关**：完全未检（额度限制），只验证了同 provider 内换模型。
2. **H1／H2**：不可分辨（0/12 vs 0/12；n=1）。
3. **能力-价值曲线**：仅三点阶梯（4-flash／4.5／4.7），更高世代受限（`glm-5.3-flash` 为付费门槛）。
4. **多臂因额度中断未跑满**（W 12/12、WE 4/12、S/SE 作废）——已隔离 29＋1 行。
5. **n 普遍偏小**（比值型结论 n=12；真机抽检 n=2，仅存在性证据）。
6. **token 真值不可得**（宿主不回传用量，以步数／上下文字节为代理）。**2026-10-16 更正**：宿主已回传 `usage`（含 `cacheReadTokens`）——该约束解除，见 `docs/design-specs/layer3-quantification-results-20261016.md` §2b。
7. **本插件的判据实现自身出过四次缺陷**（分类器三修、副作用、解析、留存证明）——已修，但说明"判据自检"是必需项而非可选项。
