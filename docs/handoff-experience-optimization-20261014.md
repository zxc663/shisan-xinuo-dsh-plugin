## 5. 已知坑（接手方**必读**，每条都真踩过）

1. **工具面被 L1 锁死且不可升**：本会话 `wire=10`；`web_search/web_fetch/job_output/job_list/job_kill/skill/…` 全被裁。**恢复只在会话外**（`discipline_tools` 无恢复能力）。会话内任何"授权"都不生效。
2. **`subagent` 可见但 `job_output` 被裁** ⇒ 派出的后台子代理**无法主动取回**，只能等推送；**别指望取结果，宁可前台做**。
3. **`pwsh` 工具在本会话不可用**（沙箱授权 `SetNamedSecurityInfoW Win32 5`）。可用的真实执行通道＝`discipline_gate` 的 `cmd`（走 cmd.exe）。
4. **`cmd` 只吃 shell 命令**：`path_contains:…` / `cmd_exit0:…` 等**算子是给断言用的，不是命令**；当命令用必然 `exit 1`，且会被记成"你的不符"。
5. **`cmd` 的相对路径不可靠**（cwd 未定义）⇒ **收口判据一律写绝对路径**。
6. **阶梯与额度跨任务累计**（T3／T4）：长会话里前一个任务的失败/强制会吃掉后一个任务的余量。
7. **`discipline_task` 默认关**：想用断言须会话外 `SHISANUO_ASSERT_LAYER=1`。
8. **改包先重编**：本仓源码在 `src/`，但**实际加载的是宿主 profile 里的副本**（`cordis.yml` 的 `file://` 直载）；改源码未必等于改运行态——真机故障优先怀疑"常驻进程用旧副本"。
