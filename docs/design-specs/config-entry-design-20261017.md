# 配置入口设计（冻结）· 2026-10-17

> 性质：**设计冻结档**（先设计、后立项施工；本档不含实现）。依据=《配置入口惯例调研》（`config-entry-research-20261017.md`，一手生态证据）＋本仓既有原则（`extension-design-20261014.md` §C/D、`todo-next` D5、README 红线）。
> 一句话：给插件补上**符合 DSH 生态惯例的用户配置入口**——侧栏「插件」→ 本插件卡片 → 设置页（三个分区），**UI 是叠加层、文件永远是权威层**。

## 1. 定位与不变量

1. **配置权限与执行权限分离（D5）**：入口面向的"配置权"只覆盖**数据面**（规则包、纪律文本的取值）与**审计面的只读呈现**；**执行权限链、判定语义、拦截与收口机制不在入口的任何可编辑面内**。红线（沿用）：入口只允许**加强**方向（加审计、加来源标注、加校验），不得出现"放宽/绕过/美化判定"的开关。
2. **文件=权威层**：`content/rules.json`、`content/discipline.md`、环境变量、profile patch 保持为**唯一权威配置源与完整功能路径**；UI 任何时期都不得成为唯一入口（headless / 无浏览器半 / 宿主升级碎裂时，功能不残废）。
3. **降级不欺骗**：浏览器半缺失时卡片不出现，**不显示"假成功"文案**；文档与 README 标注入口的可选性。
4. **来源可辨 / 证据贴结论 / 一行默认按需展开**（extension-design §C 三条，逐条适用）。

## 2. 入口形态（冻结）

- **位置**：侧栏「插件」页 → 本插件卡片（社区分组）→ 打开设置页；宿主若为"自动派生代际"，则同一设置页由宿主渲染（见 §4 兼容矩阵）。
- **设置页分区（三卡片）**：
  1. **执行账本**（Audit）
  2. **规则包**（Rules）
  3. **纪律文本**（Discipline）
- 卡片标题与文案遵循惯例：本地化标题＋一行描述＋展开看详情；状态标签只标**异常态**（如"校验失败""来源=自定义"）。

## 3. 三卡片定义（分期与验收）

### C0 执行账本（只读）— P0（首发）
- **内容**：最近 N 回合计（默认 20）：回合/GATE 分布（ok-tool / ok-auto / ok-effect / gate-fail / unverified / skip）、steer 计数、未闭环清单、L3 命中与拦截计数；聚合来源=**复用 tally 现有聚合逻辑**（同一算法、同一口径）。
- **隐私边界**：只显示**聚合与计数**；不提供正文导出；脱敏约束套用现行写入前处理；面板注明「数据目录可用 `SHISANUO_LOG_DIR` 指向私密位置」。
- **验收**：卡片在插件页可见；面板各计数与 `node scripts/tally.mjs --report`（同一日志）**逐项一致**（可对照）；无日志时显示空态说明而非报错。
- **零写风险**：该卡无任何写操作。

### C1 规则包（只读 → 编辑）— P1
- **只读版**：显示生效源（`SHISANUO_RULES` 或 `content/rules.json`）、加载校验状态与失败原因、域清单与条目数（数据源=启动自检与 `rules` 落账字段）。
- **编辑版（独立子项）**：草稿式表单（增删改条目、语法校验、diff 预览）→ 保存=「校验全部候选→原子写回→生效方式提示」；**依赖项：规则热重载**（现状规则在 boot 读取；插件侧需先有 reload 能力——该能力未实现前，编辑版仅提示"重启生效"，不做假热更）。
- **验收（只读版）**：显示值与实际加载值一致（含自定义源场景）；校验失败时原因可读。
- **验收（编辑版）**：非法输入阻止保存并说明原因（逐字段）；保存后文件 diff 仅含预期变更；失败时原文件未变。

### C2 纪律文本（只读 → 编辑）— P2
- **只读版**：生效源（`SHISANUO_DISCIPLINE` 或 `content/discipline.md`）、字节数与段指纹（复用 `self-check` 数据）——"镜像一致性"风险（正文与系统段漂移）在此可见。
- **编辑版**：依赖同 C1（热重载）；同时在页内明示"修改文本=修改模型可见纪律面，不改变执行层机制"。
- **验收**：只读版指纹与启动自检落账值一致。

## 4. 技术形态（决定项，不入本档实现）

| 项 | 决定 |
|---|---|
| 结构 | runtime 半（现有，零改动）＋ **新增浏览器半**（独立入口文件；`dsh.client.platform=web` 同生态惯例） |
| 与宿主代际兼容 | **双轨**：①注册式（`configForms`＋插件页 slot 卡，适配现行 0.2.0-rc.2 线）；②派生式（暴露 Config schema 由宿主渲染，适配新代际）。两轨共用同一配置数据模型与文案字典 |
| 写回 | 有编辑功能的卡片沿用生态惯例：**先校验候选→原子写回→保留注释与 `!!js`→失败回滚**（若自管写回，先备份再写；若宿主提供 config 编辑器服务则优先复用） |
| 依赖面 | 仅使用宿主提供的外部件（ui primitives 等），不引入运行时依赖（对齐 lazy-tools 的 externals 纪律） |
| 降级 | 无浏览器半/宿主不支持 → 卡片不注册；一切功能继续经文件路径可用 |

## 5. Non-goals（明确不做）

- 不做配置授权体系（登录/角色/远程权限）——那是宿主面；本入口只做本地单用户配置。
- 不做远程同步/云备份；不做主题/皮肤；不做 i18n 扩展（跟随宿主语言即可）。
- 不改判定语义、不新增运行时能力、不放宽任何拦截/收口行为。
- 不把"发行为可安装形态"与入口捆绑——对外动作仍按冻结逐项批。

## 6. 风险与回滚

| 风险 | 处置 |
|---|---|
| 宿主升级碎呈现层（历史教训：patternMode 连坐） | 呈现层独立、可缺失；核心治理零依赖入口；碎时自动降级为"无卡片" |
| 写回损坏配置 | 校验前置＋原子写＋失败恢复（生态同款机制）；只读卡零风险 |
| 口径漂移（面板数字 vs 报告数字） | 强制"复用同一聚合函数"＋验收要求逐项一致 |
| 入口成为配件死角 | P0 只读面板先上线验证使用率，编辑能力按依赖与需求再开 |

## 7. 与现状的关系与施工前置

- 本档=**设计冻结**；施工需独立立项与批准（沿用"设计确认先于写码"）。
- 施工前置（按序）：①浏览器半打包与宿主装载路径实测（0.2.0-rc.2 线，参照 lazy-tools 的 `__ModuleLoader__` 形态）；②P0 面板与 tally 聚合同源化改造点清单；③（编辑版）规则/文本热重载能力设计。
- 与发布冻结的关系：**不变**。本档不改包面版本与对外动作。
