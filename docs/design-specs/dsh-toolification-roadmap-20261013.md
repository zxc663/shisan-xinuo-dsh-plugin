## 1. 现插件工具面诚实盘点（30/70）

已是真工具层（约 30%）：
- L3 pre-execute 拦截：宿主代码正则+审批卡，模型绕不过执行层（A 臂对照实测：模型自判不拦、插件拦才停）。
- GATE 机检+behavior 指标：turn/end 宿主判分落 exec-log，不信自报。
- 状态横幅：每请求动态装配（位置杠杆的应用）。

仍是提示词层（约 70%，用户批评命中处）：
- 判级（什么是 L3）大部分靠模型自判；正则只盖 6 域枚举。
- 复述/状态行/GATE 六字段=要求模型表演文本。
- 必问底线/回滚点/验证两负载=零强制。
- **关键承认**：正则枚举=提示词思维的宿主侧镜像——枚举永远追不上绕过（python -c/node -e/脚本文件即漏），天花板与提示词同源。拦截面是硬的，覆盖面是软的。

## 2. 深层原因（为何困在提示词层）

1. **agent 可达性偏置**：模型能直接写的是文本；工具层要读宿主源码、冒兼容险。方案自然向「顺手能做的」而非「问题需要的」收敛。
2. **验证框架路径依赖**：A/B 四指标（复述率/判级率/GATE 出现率/L3 停点率）全部度量模型输出文本形态——仪器本身提示词中心，指标决定优化方向。
3. **本体论惯性**：shisan-xinuo 把纪律存为 405 条文本，「纪律=可读文本」是体系本体假设。用户转向=本体论革命：**纪律的落点应是工具结构，文本只是工具的说明书**。

## 3. 工具化路线图（按命题设计，可行性已核）

宿主能力证据（asar 文本机检，2026-10-13）：
- `registerTool(name, { inputSchema: z.object({...}) }, async (args, ctx) => {...})` 文档示例在宿主内 → **插件可注册自定义工具**。
- 运行时有 `tool-addition` 更新类型 + `deferLoading` 标志 + tools diff 逻辑 → **工具面可动态增删**。
- 未找到公开的「隐藏既有工具」API（removeTool 命中系 UI 误报）→ 隐藏面可能需 intercept/isolate 或不可行，施工批核实。

| 步 | 动作 | 对应命题 | 价值 | 风险 |
|---|---|---|---|---|
| T1 旗舰 | **gate() 工具**：收口=调用工具而非输出文本。宿主真跑 cmd、真取 exit 码、字段落 exec-log；模型自报与实测不符=打回重做 | 三/一/七 | 消灭假 GATE；证据三挂靠从自报变机检；A/B 指标升级为工具调用合规率 | 低（纯新增，不碰既有面） |
| T2 减法 | **工具/技能预算器**：会话按任务裁工具面（deferLoading 机制已在）；「装多少背多少」→「用多少装多少」 | 四/五/六 | 直接砍 31.2K 三头鲸中的两头（工具 schema+技能列表） | 中（依赖隐藏面 API 核实） |
| T3 替换 | **受控执行器**：wrap shell 工具——白名单+审计+回滚点检查（git 仓内未 commit 的破坏性操作先拦）；危险域不再靠正则枚举 | 一/七 | 改变动作空间本身（没有裸 rm，只有受控删除），枚举天花板消失 | 高（动核心工具面，兼容验证重） |
| T4 观测 | 指标从文本面迁工具面：工具调用合规率/拦截覆盖率/误放率/预算命中率；judgeRestated 形态正则→契约结构检查（五项键位）+「主动澄清重要歧义数」计数（外审③：现机检奖励表演性复述） | 二 | 验证仪器与形态同代 | 低 |

顺序=T1→T2→T3；每步独立可回滚（--patch 形态拔掉即恢复）。
提示词不删：工具到位后纪律段 v2 退为「工具说明书」（更短），文本退位而非消失。

## 5. 六问机制设计（2026-10-13 用户第二裁决：两本质+六问）

> 两本质：①DSH 开源框架，一切可改可读（「未找到 API」=「还没读够源码」，不是边界）；②工作流=被安排好的确定性机制，提示词只是其中一种材料。
> 「凌驾」的实现=工作流运行在宿主进程（模型不可见不可改的层），模型只能看到工作流选择暴露的接口。模型层永远可绕过；宿主层绕不过。

### 5.1 纪律靠什么强制保证（分层答案）

| 层 | 内容 | 强制方式 |
|---|---|---|
| 宪法层 | 核心纪律 ~1K 字符（L3 六项/密钥/不假实现/回滚点） | 常驻注入+**工具强制**（gate() 验证 exit 真值、受控执行器拦危险域、机检扫描） |
| 流程层 | 复述先行/判级选道/收口 GATE | **编排强制**：宿主决定供给顺序与工具可用性（未复述→任务工具不装载；未 gate→turn 不判定完成） |
| 判断层 | 边界拿捏/方案选择 | 提示词+按需细节纪律（5.6）——唯一保留软约束的层 |

### 5.2 工具/Skill 路由（装了一堆技能和 MCP 时）

现状病根：平台把全部工具 schema+技能简介发给模型自选（31.2K 三头鲸之二）。
工作流优化=**接管路由**，模型只做最终选择不做全量浏览：
- 第一级（宿主确定性路由）：任务特征（判级/关键词/文件类型/会话历史）→ 工具子集+Skill 候选 2-3 个。机制=deferLoading/tool-addition（已在宿主运行时）。
- 第二级（模型选择）：只见候选子集的完整定义。
- 判级信号现成：L1 装最小集；L2-F 才装完整工作流工具（gate/memory/error_router）。
- 效果：上下文从「平台有什么」变「这个任务需要什么」——命题四（倒 U）的机制解。

### 5.3 经验回流与用户反馈

- **回流自动化**：错误发生→error_router 查教训库→返回处置建议→处置结果回写（命中计数+1）；同坑计数达阈值→晋升建议卡（人工确认后入库/升全局）。「同坑两次晋升」从主控自觉变宿主计数。
- **给用户的反馈面**：拦截卡/处置卡实时可见（「按教训 #N 处置，命中第 3 次」）+周期性回流报告（本周期新增教训/高频坑/未命中错误）。
- **别的用户**：开源形态下教训库=数据文件（lessons.jsonl，platform 字段见 5.5）随插件分发；用户反馈通道=issue 附 exec-log 样本→维护者评审入库；社区池+本地池两层（本地优先，社区池按需拉取）。工作流第一次变成「可分发的数据+机制」而非「一篇文章」。

### 5.4 经验库存哪、何时用、更好方式

三层归属：
- **平台级**（跨项目通用教训）：插件管理，随插件分发。
- **项目级**（本仓库特有）：项目仓库内（随 git 走，可评审可回滚），替代现在的 gitignore memory 孤岛。
- **会话级**（临时状态）：进程内存，会话结束按值晋升或丢弃。
- 使用时机=**查询点工具化，不预载**：错误发生时（error_router 自动查）+判级后（按级别预载该级流程包）。库可以很大，上下文只进命中条目——「存集中，用按需」。
- 更好的方式=库与上下文解耦：教训价值在「被查询时返回处置」，不在「被注入时占位」。

### 5.5 错误 TOP 的平台归属（必须正确区分）

现有 TOP 混装两平台，迁移前逐条标 platform 字段：
- **参照环境特有（DSH 不发生）**：#294 Edit not read（DSH 基座自带 read-before-edit 政策——瘦身时删除正确）；hooks 通道类。
- **DSH 特有**：插件事件信封解包（{type,seq,data} 包裹）；cordis 加载路径（file:// URL）。
- **通用**（构建/进程/HTTP/认知）：#228 改包先重编、#229 常驻进程旧 dist、#233 命名直觉、#256/#269/#262 异步与深拷贝。
- 规则：A 平台的坑不装到 B 平台（假阳性处置）；通用条目双平台各自实证后才标通用。

### 5.6 细节纪律按需供给（不作为 Skill）

核心纪律常驻全量先知；细节纪律由**系统工具判断时机供给**，三种供给点：
1. **判级后**：按级别装配对应流程包（L1=三行快速通道；L2-S=短跑道清单；L2-F=完整九步）——systemPrompt.section 动态 text()（状态横幅同机制，已在码）。
2. **错误发生时**：错误签名→TOP/细则命中条目作为 error_router 返回值供给。
3. **动作进行时（位置最优）**：相关纪律作为**工具返回值携带**——模型调用受控执行器→结果旁附「此刻适用：回滚点未建，本次操作需先建」；调用 write 类工具→旁附对接清单。纪律紧邻动作出现=位置命题（二）的极致应用。
- 设计原则：纪律从「开场白的一部分」变「动作的伴随物」。

## 7. 运行时控制模型 v2（2026-10-13 第四轮外审：产品本质重定义——本档新脊柱）

> 外审承认前轮分类错误（把本插件当 Skill 打包发行版评估）后重调研：产品本质=**把依赖模型自觉的工程纪律转化为宿主运行时可执行的流程控制**。定位假设（待 E1 验证，非创新性证明）：「为 DSH Agent 提供一层风险自适应的运行时流程控制：按任务状态和风险决定哪些操作可以执行、哪些流程条件必须满足、什么真实证据足以允许进入下一阶段或正常结束。」

### 7.1 任务状态机（脊柱）

```
待理解 → 待澄清(如需) → 待批准 → 执行中 → 待验证 → 已完成
```
- 转换条件由**插件可执行逻辑**维护，模型语言声明（「已进入执行」「已验证」）不构成转换。
- 例外走显式登记（用户授权例外记录在案），不伪装成正常通过。
- **三级跑道=风险自适应深度预设**（heritage 映射）：L1=短状态链（理解→执行→验证）、L2-S=中链、L2-F=全链——「不是所有任务走完所有状态」由判级天然承载。

### 7.2 状态门控与证据三分离

- **受控操作面**：副作用类工具（写/执行/删）按状态门控（如未达「待批准」→修改类调用拒）；只读类豁免。**边界如实**：仅覆盖受控路径，绕过面=_E1_ 固定测试项（替代工具/替代命令同副作用）。
- **证据三分离**：产生（真实工具执行）≠判定（确定性退出码+判据）≠转换（判定满足才许改状态）；退出码零≠任务正确（取决于命令测了什么）。
- 官方扩展点映射〔事实，官方文档〕：agent/pre-step（阶段前提检查）/tools/pre-execute+guard 单调拒绝（门控执行）/restrict（按阶段收工具面）/post-execute+tools/result（结果证据）/agent/turn-stopping+steering（缺验证时阻止收尾）。

### 7.3 T1-T4 重映射（功能列表→脊柱部件）

| 部件 | 状态机角色 | 既有资产 |
|---|---|---|
| T1 gate() | 待验证→已完成的**证据转换器** | v0.2 施工 |
| T2 预算器 | 风险自适应**深度选择器** | 三级跑道判级信号现成 |
| T3 受控执行器 | 待批准门的**状态门控权限执行器** | L3 拦截已在产（pre-execute+guard 形态） |
| T4 观测 | 状态转换指标（见 E1） | exec-log |

### 7.4 E1 升级三臂（外审 §五采纳，替代原 A/B 两臂）

| 臂 | 条件 | 回答 |
|---|---|---|
| A | 裸 DSH | 原本怎样执行 |
| B | 现有工作流 Skill+规则 | 纪律文本+现有门禁改善多少 |

## 6. 修订后总架构（一张图）

```
模型层（软：判断/生成，只能看到工作流暴露的接口）
   ↑ 受控接口
工作流层（硬：DSH 宿主进程内确定性代码）
   ├─ 宪法供给：核心纪律常驻 ~1K
   ├─ 路由器：任务特征→工具子集+Skill 候选（5.2）
   ├─ 工具网关：L3 拦截/gate() 真值验证/回滚点检查（5.1）
   ├─ 纪律路由：判级/错误/动作三供给点（5.6）
   └─ 经验层：教训库三层+error_router+回流计数（5.3/5.4）
DSH 框架（开源，一切可读可改——本层的任何「不可行」都只是「未读够源码」）
```
