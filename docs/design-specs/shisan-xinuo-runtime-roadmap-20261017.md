## 1. 目标与原则

**总目标**：把「工程纪律」做成三层可验证体系——常驻提示词（模型可见面）＋渐进加载提示词（按需面）＋运行时强制（执行面），让治理成本按任务复杂度付费、让确定性检查不依赖模型记忆。

**设计原则（每条有出处）**：

| 原则 | 内容 | 出处 |
|---|---|---|
| P1 检测触发注入 | 强制提示只在检测到缺失时注入（判级缺失/清单缺失/压缩信号），不常驻注入 | 用户讲解「工具要检测模型的输出来进行提示注入（减少 token 消耗）」 |
| P2 边界优于枚举 | 拦截优先用「工作区边界」这种确定性判据，L3 命令正则降为兜底层 | 用户讲解「检查有没有越过工作区…而不是仅拦截 L3」 |
| P3 权限分层 | 三档权限（只读查看/工作区内操作/完全权限）语义分离；完全权限=记录不弹卡 | 用户讲解「DSH 三个权限…完全权限转为记录」 |
| P4 停点分层 | 严重停点必须等人；目标模式普通提问带倒计时 | 用户讲解「不能因为阻碍而阻碍，也不能不应阻碍而继续」 |
| P5 输出零重复 | 收口证据并入模型输出结尾，模型不复述 | 用户讲解「收口工具混入到模型的输出中…而不是让模型输出两遍」 |
| P6 压缩不降智 | 压缩后默认重载技能保精度 | 用户讲解「压缩之后发信号…一般默认都是需要保持精度的」 |
| P7 盘点双源 | 开工盘点系统工具＋工作区技能/命令/脚本 | 用户讲解「不仅只盘点系统给的还要盘点工作区」 |
| P8 渐进强制分级 | 加载按 M（强制）/S（按症状）/X（不加载）三档 | 用户讲解「什么时候应该是强制的什么时候不应该是强制的…考虑明白」 |
| P9 只写不改 | 内容层与实现层分离：提示词文件先行，引擎改造后行，逐批验收 | 本次任务边界 |

## 3. 功能规划（F1–F12）

### F1 判级强制与追加判级
- 机制：解析模型首条输出 `L=` 状态行；缺失→steer 强制补判级（一次性，走现有熔断）；用户追加消息后检测是否给新判级，未给→注入「追加判级（升档/维持）」提示。
- 依赖：B1/B7（steer 通道已有）；需新增「任务内追加消息检测」（对照 R20 每条用户消息开新任务——追加识别需要任务键语义扩展）。
- 验收判据：a) 10 会话中判级缺失回合 100% 收到强制注入且不重复注入；b) 追加后升档场景（如追加删除）100% 触发追加判级提示；c) 纯聊天回合 0 误注入。

### F2 任务清单强制（L2 复杂任务）
- 机制：discipline_task 扩展「任务清单＋验收断言」登记（register 附需求项清单字段）；运行时检测「判级 L2-F 但无登记」→开工侧注入登记提示（补现有开工侧缺口，§4.1）。
- 依赖：B5（工具已有，扩参数）；F1（判级强制先落地才有可靠触发源）。
- 验收判据：a) 复杂多需求任务登记率从历史 0/自发 1/3 提升到 ≥80%；b) 语义型任务（无可机器断言）走 exempt 声明，不伪造；c) 登记内容与用户原文要求可对账。

### F3 工作区边界守卫（三档权限）
- 机制：按 DSH 权限档执行——只读查看=禁一切写；工作区内操作=禁越区写（写目标路径前缀不在工作区→拦截）；完全权限=不拦截、全量记录。判定走工具参数里的路径解析＋宿主沙箱模式事件（src 已有 sandbox/mode 事件，L1748-1757），**不依赖命令正则、零 token**。
- 依赖：宿主 sandbox/mode 事件（已证实存在）；工作区边界配置面（新增）。
- 验收判据：a) 只读档写操作 100% 拦截；b) 工作区档越区写 100% 拦截（≥10 例越区语料）；c) 完全权限档 100% 记录不弹卡；d) 合法跨区场景（显式授权/多仓任务）可通过配置放行。

### F4 L3 重定位（硬移植批评吸收）
- 机制：三层防线定位——第一层=F3 边界守卫；第二层=L3 命令正则（保留，定位=命令形态兜底）；第三层=文本红线（v4 已加「形态绕行同样违规」）。README/文档如实标注 L3 覆盖面边界（正则天花板：写工具目标替代、API 副作用、UI 操作拦截不到）。
- 验收判据：a) 文档中 L3 不再被描述为「完整拦截」；b) 已知绕行形态（write 清空代删除）在红线文本中显式违规；c) 三层层级在 README 与 SECURITY.md 同步。

### F5 完全权限记录模式
- 机制：F3/F4 在完全权限下全部转「记录」不弹卡（现状 B2 已对 L3 如此，扩展到边界守卫）；审计面不缺失。
- 验收判据：完全权限会话中拦截次数=0、记录条目=动作数（100% 对账）。

### F6 提问倒计时参数（ask_user_question 升级）
- 机制：提问工具新增 `countdown` 参数——严重停点（L3/密钥/破坏性）不设超时；目标模式必带超时，超时按预设默认（推荐项）继续并如实记录「已按默认继续」。
- 通道选择（先探针后施工）：①宿主提问工具原生支持（需宿主升级/PR）；②插件包装层（拦截 ask 决策并加超时语义，成本更高）。探针先行，不盲施工。
- 验收判据：a) 目标模式无人值守会话 0 次因提问卡死超过超时阈值；b) 严重停点提问 0 次被超时放行；c) 超时默认继续均有记录行。

### F7 收口证据并入输出
- 机制：gate 通过后，收口证据行由宿主在模型输出结尾追加渲染，模型不复述（现状 STEER_ANTI_REPEAT 只约束不重复，渲染合并为增强）。
- 通道选择：宿主渲染面（assistant message 结尾追加）> 插件 message projection（本插件红线：只用于「加强」方向——追加证据属于加强，但需探针实证不破坏会话证据底座）。
- 验收判据：a) 收口回合模型输出不出现第二次 GATE 复述（≥10 会话实测）；b) 证据行可见且与工具返回一致；c) 渲染失败回退工具返回通道，证据不丢失。

### F8 压缩信号与技能重载
- 机制：宿主压缩上下文后注入信号「上下文已被压缩；默认重载技能保持精度」（形态=notice 通道，复用 SKIP_INTERROGATION 同款信封 src L94-96）；模型按 compression-reload.md 重载序执行。
- 依赖：宿主压缩事件（需探针：是否有 session 压缩事件可订阅）；无事件则用上下文量阈值启发（次选）。
- 验收判据：a) 压缩发生后信号送达率 100%；b) 压缩后回合模型复述任务本质+当前步骤（judgeRestated 形态）≥80%；c) 纯闲聊压缩 0 注入（或注入但模型声明跳过）。

### F9 环境盘点（运行时增强）
- 机制：开工注入「工作区工具/技能清单」（宿主侧扫描工作区文件+插件注册表），模型按 environment-inventory.md 用；提示词层已落地（v4 §1.2），本项只做清单注入增强。
- 验收判据：a) 盘点清单含工作区自有资产（非只系统工具）；b) 复用命中率提升（对照：盘点前后「自写已有能力」次数下降）。

### F10 渐进加载引擎（检测→注入）
- 机制：三条检测点共用「检测→注入」引擎——F1 判级缺失／F2 清单缺失／F8 压缩信号；注入目标=layered 对应分节（M 强制/S 按症状，路由表 00-加载清单.md）；分节装载沿用 fail-closed（loadTextWithFallback）＋段指纹（sectionFingerprint 同款）。
- 验收判据：a) M 级分节在触发场景注入率 100%；b) S 级无病不注入；c) 分节更新后指纹核对无漂移；d) 注入总量与常驻文本量对比：复杂任务增量 <30%，简单任务增量 ≈0。

### F11 有效性终判与发行
- 机制：n≥5 四臂（A 惰性/B 纯文本/C 全量/D 干净基线）＋脱敏对照，按 e1-v5 预注册冻结矩阵执行；发行解冻决策（tag/Release/SHA256SUMS）。
- 验收判据：按预注册判据；发行决策需显式记录。

### F12 内容层持续维护
- 机制：提示词 v4 与 layered 随运行实证修订（同坑≥3 晋升规则）；CORE_DISCIPLINE 内嵌回退文本（src L13-46）与 content/discipline.md 同步（下次实现批必做——当前回退文本仍是旧版，见设计文档 §8.1）。
- 验收判据：三级一致（content/discipline.md ＝ src 回退 ＝ AGENTS.md 副本方向）；每次修订带反向辩证记录。
