## 9. 决策记录：A 已定（2026-10-13 · 用户拍板）· 我们的作用界定

- **决策**：拦截层**完全外置**——`dsh-permission-rules` 承载 allow/deny/ask 拦截；我方只留"判级→规则"接线（M1 形态）；正则/语料层（core 约七成）退役或缩减（实施细节随 B3 给出 diff 范围后再动）。

| 维度 | 它（规则门卫） | 我们（任务治理与验证） |
|---|---|---|
| 判定单位 | 单次工具调用 | **整个任务生命周期**（开工→过程→收口→事后） |
| 拦截执行 | ✅ 它承载（规则引擎＋内置基线） | 只留接线：默认策略内容（判级/域/豁免）＋生成器 |
| 工具面 | 不改变（照单拦单） | **任务级工具预算 restrict**（实测 25→8） |
| 上下文 | 零注入（拒绝/询问理由随工具结果反馈） | **纪律注入＋状态横幅**（systemPrompt section） |
| 收口 | 无此概念 | **验收断言＋宿主真值探测＋gate（核心净增量）** |
| 收口强制 | 无 | **turn-stopping steer（已有）／veto（待探针）** |
| 风险分级 | 无（静态规则） | **判级→预算/收口强度**；进阶：热重载按判级切规则源〔B1 增项 f〕 |
| 证据 | 自身权限审计 | **exec-log＋tally 三源对账＋gate 真值表** |

## 10. 拦截口径 · 生命周期实现度 · 上游依赖治理（2026-10-13 复盘细化）

### 10.1 "拦截什么"的确切口径（A 后＝由它执行的拦截）

| 类别 | 匹配维度（它的） | 动作 | 我方旧覆盖 |
|---|---|---|---|
| 破坏性/危险命令 | `params.command` **argv 分解**（命令词/参数 token/管道签名） | deny/ask | 有（正则）→ 退役 |
| 敏感路径读写 | `paths`（工作区相对·任意深度）＋params | deny/ask | 有 → 退役 |
| 提权/下载执行等基线 | 内置 baseline（可关） | deny/ask | 部分 → 退役 |
| 外发/网络出口 | `network`（域/IP/端口/协议）＋进程级代理 | deny/ask | **无 → 新增能力**（默认跟随宿主沙箱预设） |
| 子代理/身份差异 | `agents`（main/subagent/preset） | deny/ask | 无 → 新增 |
| 写入类确认 | `tools:[edit,write]` → ask | ask（官方审批缝；可挂生态应答器） | 部分 → 退役 |
| 环境条件规则 | `when`（env/平台） | — | 无 → 新增 |

- 三态语义：`allow`/无匹配＝`next()` 委托（**不打断下游**）；`deny`＝阻断＋原因返还模型；`ask`＝官方审批缝（无应答者时 fail-closed）。
- **它拦不了的五类（拦截的固有天花板，只能在收口/验证侧解决）**：①目标替代（合法工具偷换目标——E1 三型实证）②非工具路径谎报（纯文本"我做完了"）③用户意图误读/该问不问 ④沙箱外 OS 操作（宿主职责）⑤其他插件干扰。**这五类正是 B2 必须存在的理由。**

### 10.2 任务生命周期 × 实现度（A 后归属）

强度标尺：①确定性拦截 ②强制门（依赖钩子强度）③记录/检查点 ④提示词级 ⑤空缺

| 阶段 | 典型失败 | 机制（A 后） | 强度 | 归属 |
|---|---|---|---|---|
| 接收·复述 | 理解错目标 | 纪律注入 | ④ | 我们 |
| 判级·澄清 | 误判/该问不问 | 软判定＋信号提取（→预算/收口强度） | ④→③ | 我们 |
| 计划门 | 无计划就动手 | 现状软；硬化=后续可选项 | ④ | 我们 |
| 执行·调用 | 危险调用/越权参数/外发 | pre-execute 规则（allow/deny/ask） | **①** | **它** |
| 执行·工具面 | 工具过多/不该有 | restrict 预算 | ① | 我们 |
| 执行·审批 | 高风险需确认 | 官方审批缝（ask） | ①→人 | 它＋宿主 |
| 验证 | 假验证/验错目标 | gate 真值（模型须主动调用，有 1/3 缺口） | ② | 我们 |
| 收口 | 未验证就宣告完成 | turn-stopping steer（1 次/回合；veto 待探针） | ② | 我们 |
| 收口·任务本义 | 目标替代 | **B2 验收断言＋宿主真值**（现为⑤空缺） | ⑤→② | 我们（净增量） |
| 事后 | 无证据/纠缠 | exec-log＋tally＋gate 真值表 | ③ | 我们 |

一句话：**它把"执行期单调用"做到①级；我们把"开工判级→收口验证→事后证据"整条链拼起来，并补上任务本义这个缺口。**

### 10.3 上游来源与依赖治理政策（"标明上游来源"落为条款）

- **法律层（Apache-2.0）**：仅 npm 依赖、用户自行安装 → 无再分发收编义务，但来源标注照做（见下）；若 P3 把上游包 vendor 进我们 bundle → 必须随附 LICENSE、保留其 NOTICE（如有）、对修改文件显著标注。
- **产品层（我方诚实条款）**：README「依赖与致谢」列上游链接＋兼容版本区间；**生成的规则文件头部写 provenance 注释**（"本文件由十三希诺生成器生成；由 dsh-permission-rules 引擎执行；上游：PerryLink/dsh-permission-rules vX"）。
- **内容归属界分**：默认策略内容（危险域/豁免/判级映射）版权＝我方；匹配引擎＝上游。不混淆两者。
- **版本治理＋逃生舱**：跟随其 engines 兼容区间；minor 锁版本、major 变更跑 compat 重测；生成器输出**中立规则源**——若上游停更，可换引擎或回落我方最小 matcher。

### 10.4 "更明智的选择"（清单）

1. 按**拦截类别**选引擎（类别→引擎见 10.1），不按"项目"全押；同类里它是唯一成熟件（122★/CI/兼容矩阵/审计；其余替代 1★ 级不构成选项），但"选它"≠"全押它"。
2. 保留**逃生舱**（生成器＋中立源＋可替换引擎）——对上游风险的明智对冲。
3. **分级试运行**：先 `enforce:false` 干跑，与旧拦截做对照数据，再切换——把换芯误拦风险压到最低。
4. ask 的应答器用生态（`dsh-auto-review`），不自研；输出脱敏（`dsh-guardian`）列候选、不入本批。
5. 网络出口拦截纳入口径，但默认跟随宿主沙箱预设（不擅自改安全档位）。
