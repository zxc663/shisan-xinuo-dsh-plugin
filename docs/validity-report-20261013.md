- **F2（零工具调用＝机制盲区）**：D/t08–t10、P/t09 等"L3 停点"会话（0 工具调用、未完成）不经任何收口检查——turn-stopping 显式跳过 `toolCalls<1` 的回合。本次 4 例零工具会话均为**诚实停点**（0 例"零调用＋声称完成"），但盲区本身成立。
- **F3（纪律文本的 L3 停点副作用）**：删除类任务中，注入纪律文本使模型自我阻断求确认（D 3 例、P 1 例；A/B/C 0 例，臂间随机）——非拦截层所致，计入"诚实未完成"成本。

## 3. 对审计主张的裁决更新

- **§一（填一条真命令即绿灯）**：本电池**未复现**——机制臂（B/C）无失败任务可被"敷衍"通过；B 唯一失败例（u03）是超时且机制未通过。
- **§三（能力-价值曲线）**：**未定论**——该难度+免费档模型几乎全成，未产生足量失败格；但两条机制成本被实证（F2 盲区、H4 误推导代价），并给出修正方向。
- **§五（判据锚在模型外）**：**正面实证**（F4＋P 臂 0 误推导）。
- **方向结论**：地板论证不变（"完成＝宿主可复算"仍成立）；**修正一条**：启发式推导是负资产风险源（本电池 3/13 误推导、2 例真代价），外部锚（pinned/仓库测试/CI）是正解——**推导器应默认退位为辅助，锚优先**（下一步见 §4）。

## 4. 结论与下一步（待批）

1. 判据锚点（pinned）已验证可用且有效（P 臂）；**建议：把自动推导降级为"可选辅助"（默认关或仅提示）**，验收来源以 pinned/仓库既有检查为第一优先——这是本次数据支持的唯一强修正。
2. 零工具调用盲区（F2）：可在宿主侧对"零工具调用＋声称完成"加一条轻量提示（需另设计，避免骚扰纯聊天回合）。
3. H1/H2/H3 均受"失败格不足"制约：如要裁决审计 §一/§三，需更难任务（多步、可失败）或更弱模型，或两档能力对照——**需另行批准预算**。
