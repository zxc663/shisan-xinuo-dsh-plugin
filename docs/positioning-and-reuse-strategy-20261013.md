# 定位校准与复用策略（讨论落档）· 2026-10-13

> 性质：**讨论落档 + 方向决策记录，零施工**。输入=①并行环境复盘（token 账本/竞品实况/「激进聚焦」提案）②方向校准 ③本档实查（2026-10-13，gh api 三查+文件核数）。
> 一句话：**产品定位校准（保持宽）＋实现定位收窄（复用优先）**——取代"把产品缩成单一机制"的激进聚焦。

## 0. 决策摘要

1. **产品定位（宽，不缩窄）**：本插件=DSH 上的**工作流进行时治理与验证插件**——任务状态与门、执行守卫、验收绑定与真值收口、证据与跨会话延续、纪律/能力装配。拦截层是其中一个子系统：**不砍掉**，但不再自研其主体。
2. **实现定位（窄，不铺开）**：逐子系统**复用优先**——拦截/权限层以 `PerryLink/dsh-permission-rules`（实查 122★/Apache-2.0/2026-10-12 仍更新）为主体吸收（依赖/适配/二开，P0 定）；自研资源只投"任务记录持有验收条件+真值收口"等**无同类净增量**。
3. **流程修复**："双调研"（联网+复用）在本项目**从未实际发生**——已列为产品需求（"设计前门"：触发点+产物+检查点）与流程提案（需批准后落规则）。

## 1. 账本与事实修正（采信并行复盘，附实查修正）

- **账本（采信）**：token 去向约半数=36 会话实验（认知资产：目标替代、A≈D、gate 调用率缺口）；约四分之一=四轮审计"打正则地鼠"（无净增益）；约五分之一=报告/预注册；产品代码极少——核心 `src/shisan-xinuo-core.ts` **实查 755 行**，其中约七成为正则黑名单。
- **核心失误=决策失误**：四轮审计自首轮起就指向同一句话（"拦截层不值得、收口才是净增量"），实际动作却是连续打补丁。**信号≠决策**——缺的是"方向级决策门"，不是分析。
- **竞品实查（本档 2026-10-13）**：

| 项目 | 实查数据 | 能力要点 | 结论 |
|---|---|---|---|
| `PerryLink/dsh-permission-rules` | **122★** / Apache-2.0 / TS / 更新 2026-10-12 / 未归档 | 声明式有序 allow/deny/ask；工具名+参数(glob/正则)+**工作区路径**三维匹配；挂 `tools/pre-execute` 瀑布；会话日志审计；**HMR 热重载** | 拦截层"换芯"首选主体 |

## 2. "双调研"缺口（软约束失败样本 #1 · 本次讨论最值钱的产出）

- **工作流原文要点（本会话注入版）**："设计铁律：设计前先调研成熟设计→留档 `docs/design-specs/` 并按档回指；**能复用绝不自研**——最少代码实现最完整功能=最好代码"；"双调研一次完成（联网+复用）"。
- **实况**：插件从设计走到 v1.0 验收，**未经历双调研**；`dsh-permission-rules` 这类成熟件，直到四轮审计**之后**才被撞见。代价＝约七成代码投在一个多维度落后于现成项目的自研层上，外加持续语料维护与审计地鼠循环。
- **根因（为什么"要求过却没发生"——机制层）**：
  1. 无**触发时机**：规则写"设计前"，但没有任何事件在"设计开始"这一刻触发它；
  2. 无**产物要求**：没定义调研产物长什么样、放哪里、谁消费；
  3. 无**检查点**：没有任何门在"没有调研产物"时拦住下一步；
  4. 文本规则的强制力上限=模型注意力——**恰是本插件要解决的那类问题本身**。
- **产品含义**："要求"不是机制；**机制=触发点+产物+检查点**。双调研缺口直接入产品需求（见 §5 提案 1）。
- 本档自我约束：§3 复用决策一律以实查数据（非转述）为前提，未核项标"待核"。

## 3. 复用策略（"吸收竞品"的具体化）

原则：**定位宽、实现窄；复用优先，自研须写明理由；净增量只投无同类项。**

| 子系统 | 现况 | 走向 | 复用对象与方式 |
|---|---|---|---|
| 拦截/权限层（L3 正则） | 已实现（755 行中约 70%） | **停扩停补**：停止扩旁路、审计再报正则洞=登记不修（除非误拦）；功能等价评估后**换芯** | `dsh-permission-rules`（Apache-2.0）：P0 实测接口面后定"依赖/适配/fork"；我方保留**"风险判级→有效规则集"映射层**与既有 17 例语义回归 |
| 危险命令守卫 | 正则覆盖 | 并入换芯或参考 | `dsh-guardian` 守卫形态参考 |
| 输出脱敏（密钥不出模型） | 未做 | 新候选能力 | `dsh-guardian`（MIT）脱敏思路/代码（待核后定） |
| **任务状态机+验收绑定（真值收口）** | 设计完成未施工（v2） | **继续自研（净增量）** | 无同类（竞品扫描+四轮审计双确认） |
| 工具预算/遥测/实验基建 | 已实现 | 保留 | — |
| 启动鲁棒性（插件搞崩 profile 的回滚） | 未做 | 参考 | `DSH-Guardian` 思路参考或列不做 |

- 许可证注意：Apache-2.0=依赖/fork 均可（保留 NOTICE）；MIT=宽松。二开边界由 P0 给出立项建议。
- 红线：不做"人人都有"的层的**新自研**；每个新 commit 必须对应用户可见能力或净增量。
- 与既有版本路线的关系：**v2（任务控制器+收口强制）不变**；拦截换芯作为 P1 并入 v2 批前；v3-v5 照旧——定位未缩窄，各子系统实现来源全面复用化。

## 4. 路线修正（相对"激进聚焦"三步版）

- **P0 复用调研补课**（1 小批，本次缺口修复）：官方清单全量扫描 + 同类全扫 + 逐项"复用/二开/参考/不采用"结论 + license 摘要 + 接口面实测（`dsh-permission-rules` 与我们的 guard 挂载点是否同点、HMR 与重载需求、规则 DSL 能否承载风险判级）。产物=`docs/reuse-research-*.md`；**无产物不进 P1**。
- **P1 拦截换芯**：按 P0 结论吸收 `dsh-permission-rules`；旧正则包降级为"便利默认规则"或退役；回归=误拦样本 + 16 次真宿主拦截语义不降级。
- **P2 验收绑定内核**（v2 原计划）：任务记录持有验收断言 → 收口真值校验 → 未收口不放行（追账/turn-stopping 按探针结果二选一）。以四臂谎报样本做验收。
- **P3 可安装化**：bundle manifest + npm 结构 + 三段 30s demo（谎报被打回/未收口被拦/断言绑定）。
- 纪律文本仍在母仓；插件只做机器能保证的部分。

## 5. 流程修复提案（需用户批准后落规则；本档仅登记，未改任何规则文件）

1. **设计前门**：任何"设计/选型/施工"任务开始前，必须存在复用调研产物——触发点=判级进入设计类；产物=固定模板（候选清单+实查数据列+复用结论列+license）；检查点=复述/计划门核对存在性。
2. **决策门**：审计出现方向级信号（同类反馈≥2 次）→ 强制"继续/转向"决策记录，禁止默认打补丁。
3. **产物配比**：每批代码/机制产出 ≥ 文档产出；报告膨胀触发解释。
